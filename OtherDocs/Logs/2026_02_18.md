# Development Log — Native Location Geocoding

### Date

18 February 2026

### Objective

To automatically populate geographic coordinate fields (`latitude`, `longitude`) within the speaker metadata dataset using existing `native_city` and `native_county` columns.

---

### Problem Identified

The dataset contained structured textual metadata for speaker origin:

* `native_city`
* `native_county`

However, no geographic coordinate data was present.
This prevented:

* Marker placement on Leaflet maps
* Spatial visualisation of model predictions
* Geospatial clustering or analysis

Manual entry of coordinates was deemed:

* Error-prone
* Non-reproducible
* Infeasible at scale

---

### Technical Approach

An automated geocoding pipeline was implemented using:

* Python
* `pandas`
* `geopy`
* OpenStreetMap Nominatim API

The process:

1. Combine `native_city` and `native_county`
2. Append “Ireland” to constrain search domain
3. Submit structured query to Nominatim
4. Extract latitude and longitude
5. Cache duplicate lookups
6. Write enriched dataset to new CSV

---

### Key Implementation Decisions

| Decision                  | Rationale                           |
| ------------------------- | ----------------------------------- |
| Use Nominatim             | Free, open-source, reproducible     |
| Apply 1-second rate limit | Compliance with API usage policy    |
| Cache results             | Prevent redundant API calls         |
| Create new CSV output     | Preserve original dataset integrity |

---

### Data Processing Logic

For each row:

```
native_city + ", " + native_county + ", Ireland"
```

Example:

```
"Cork, Cork, Ireland"
```

Returned:

```
51.8979, -8.4706
```

Two new columns were appended:

* `latitude`
* `longitude`

---

### Limitations Identified

* Ambiguous town names may produce inaccurate centroids
* City-level resolution may not represent precise birthplace
* Some rural locations may fail geocoding

Mitigation strategy:

* Fallback to constituency centroid (for TDs)
* Manual validation of failed geocodes
* Future integration with official Irish geospatial datasets

---

### Outcome

The enriched dataset now supports:

* Marker placement on interactive maps
* Spatial accuracy evaluation
* Visual comparison between predicted and native province

This significantly strengthens the geospatial component of the system.

# 2️⃣ Development Log — Single-Page Bootstrap Front-End Prototype

### Date

18 February 2026

### Objective

To design and implement a minimal, demonstration-ready, single-page front-end interface for user accent classification and geospatial visualisation.

---

## Design Rationale

The front-end was intentionally constrained to:

* A single page
* Three equal vertical sections
* No navigation bar

This approach was chosen to:

* Emphasise model interaction
* Reduce user friction
* Provide a clean demonstration environment
* Focus on core system functionality

---

## Layout Structure

Using Bootstrap 5 grid:

```
col-lg-4 | col-lg-4 | col-lg-4
```

Three sections:

| Section | Function                           |
| ------- | ---------------------------------- |
| Left    | Voice recording interface          |
| Middle  | Prediction display and interaction |
| Right   | Leaflet map visualisation          |

---

## Section 1 — Voice Input Panel

Features implemented:

* Prompt text display
* Adjustable recording time limit
* Microphone recording via MediaRecorder API
* Recording progress bar
* Retake functionality
* Optional self-reported native province
* Audio preview before submission

### Design Decision

Self-reported province is optional to:

* Respect user privacy
* Allow evaluation of prediction correctness
* Enable future model evaluation research

---

## Section 2 — Prediction Panel

Displays:

* Current predicted province
* Confidence score
* User feedback buttons ("Seems right" / "Seems wrong")
* Scrollable list of past submissions
* Click-to-focus map behaviour
* Audio playback for each submission

### Design Decision

User feedback is stored separately from correctness:

* If native province selected → compute objective correctness
* If not selected → store subjective feedback only

This enables later analysis of:

* Model accuracy
* User perception of accent identity

---

## Section 3 — Interactive Map (Leaflet)

Map functionality:

* Base OpenStreetMap tiles
* Province highlight on prediction
* Markers per submission

Marker colours:

| Colour | Meaning              |
| ------ | -------------------- |
| Green  | Prediction correct   |
| Red    | Prediction incorrect |
| Blue   | Correctness unknown  |

Fallback logic:

* If native coordinates available → use exact lat/lon
* Else → use province centroid

---

## Technical Stack

| Layer              | Technology              |
| ------------------ | ----------------------- |
| Layout             | Bootstrap 5             |
| Map                | Leaflet.js              |
| Recording          | Web MediaRecorder API   |
| Data Handling      | JavaScript              |
| Future Integration | Django REST / Flask API |

---

## Architectural Significance

The front-end prototype validates:

* End-to-end user interaction
* Real-time prediction feedback
* Geospatial visualisation integration
* Dataset-to-map workflow

It demonstrates feasibility of the full system architecture described in:

* Section 4 — System Design
* Section 6 — System Prototype
